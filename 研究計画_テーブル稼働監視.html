1. 目的・概要

Raspberry Pi と USB Webカメラで構成するエッジ端末上で、軽量物体検出モデル YOLO26n と追跡アルゴリズム ByteTrack を動かし、飲食店の座席ごと・テーブルごとに「空席/着席」「利用時間」「利用人数」「稼働率」をリアルタイムに判定する。判定結果は数値データ(JSON)のみを Cloudflare(Serverless)へ送ってダッシュボードに表示し、映像はクラウドへ送らず保存もしない。参考事例(Abdul Ahad Raza 氏:YOLO26x+ByteTrack、カメラ1台・6卓、1.5秒滞留で着席判定)に対し、本研究は ①安価なエッジ端末で動かす ②座席形態・配置が不規則な約100席の実店舗規模に複数カメラ・複数エッジで対応する ③複数カメラの判定をクラウド上で統合する、点を新規性とする。開発は Claude Code による Vibe Coding で行う。

2. システム構成と各部品の役割

部品役割・機能
Webカメラ
(1080p・広角120°)		 担当座席を固定アングルで撮影する唯一のセンサー。USB(UVC)接続、MJPEG で約1枚/秒を処理。対面席は横方向、カウンターは内側正面から撮る。映像はPiのメモリ上で処理後に破棄。
Raspberry Pi 5 / 1GB
(エッジ端末)		 カメラ最大4台分の推論・判定・送信を行う。Raspberry Pi OS Lite、systemd で自動起動・自動再起動、NTP 時刻同期、NCNN のみで推論(PyTorch 不使用)、アクティブクーラーで冷却。
主プログラム
(Python・Pi上)		 ① 映像取得 → ② 人物検出(YOLO26n/NCNN、入力640px) → ③ 追跡(ByteTrack) → ④ 座席区域判定(人物枠の下1/3中央点が座席多角形に入るか) → ⑤ 着席判定(3回連続≒3秒で着席、離席は10秒猶予。立位・高速移動は店員として除外) → ⑥ 送信(状態変化時に即時、30秒ごとハートビート、失敗時は SQLite に保存して再送)。設定は起動時にクラウドから取得、カメラ故障時はその席を判定せず再接続。補助ツール:座席区域を描く draw_zones.py、平面図からカメラ配置を計算する plan_coverage.py(予定)。
Cloudflare
(Serverless)		 Workers:受信API(APIトークン認証)とダッシュボードの配信／D1:座席・卓の状態と利用履歴、設定／Durable Objects:店舗ごとに複数カメラの観測を統合(主カメラ優先、隠れ・故障時は予備カメラ)し WebSocket で即時配信(段階2で実装予定)。無料枠内で0円/月。
開発PC + Claude Code 全ソースコードを Vibe Coding で作成。開発PC → GitHub → 各Pi(git pull)、Cloudflare へは wrangler deploy。
